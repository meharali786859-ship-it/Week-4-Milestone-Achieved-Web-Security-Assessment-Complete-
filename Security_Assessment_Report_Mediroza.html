1 Executive Summary

A black-box web application penetration testing assessment was conducted against https://medirozohospital.com as part of the Week 4 Cybersecurity Capstone Project. The objective was to emulate real-world adversary tactics, identify structural security weaknesses, validate potential exploit paths, and assess the risk posed to hospital assets, patient privacy, and regulatory compliance.

During the assessment, a total of 9 security vulnerabilities were identified. Crucially, 3 CRITICAL vulnerabilities were successfully validated, posing catastrophic risks to hospital operations and data confidentiality:

  • Critical Finding #1 (Directory Indexing): Enabled directory listings on sensitive hospital endpoints (/patient/, /staff/, /old/) allowing unauthenticated directory browsing.
  • Critical Finding #2 (Full Database Backup Exposure - M3): Publicly downloadable MySQL database backup file (mediroza_db_backup_2019.sql) containing unencrypted staff monthly salaries (in ZAR), National ID numbers, phone numbers, and shareholder corporate equity records.
  • Critical Finding #8 (SQL Injection Authentication Bypass - M1): Vulnerable SQL concatenation on the Patient Portal login form, permitting total authentication bypass and administrative access using standard SQL injection syntax.

The target infrastructure is hosted on a LiteSpeed Web Server running Mediroza CMS 1.4.2. All testing was executed within educational and authorized black-box constraints. In accordance with guidelines, no defensive patches or file modifications were made during the test.

4 Detailed Vulnerability Findings & Proof of Concept

[CRITICAL] 1. Directory Indexing Enabled Across Hospital Directories

CRITICAL (CVSS 9.1)
Affected Endpoints: https://medirozohospital.com/patient/, /staff/, /old/
OWASP Category: A01:2021 - Broken Access Control / Security Misconfiguration

Description & Vulnerability Analysis

The LiteSpeed web server is configured with Directory Indexing (AutoIndex) enabled. When an HTTP GET request is dispatched to directories without a default index file (e.g., index.html or index.php), the server dynamically creates an HTML table displaying the complete directory listing, including filenames, modification timestamps, and file sizes.

Business & Security Risk

Directory indexing transforms passive browsing into active reconnaissance. Any unauthenticated user can discover confidential files, backup archives, scripts, and patient reports without needing brute-force fuzzing.

Figure 3: Proof of Concept - Unauthenticated directory indexing on /old/ exposing database backup archive Finding #1 Evidence

🛡️ Remediation Strategy

Disable directory indexing globally or on a per-directory basis. In LiteSpeed WebAdmin Console or via .htaccess:

Options -Indexes

[CRITICAL] 2. Sensitive Database Backup Exposed in /old/ (M3 Milestone)

CRITICAL (CVSS 9.8)
Affected File: https://medirozohospital.com/old/mediroza_db_backup_2019.sql
OWASP Category: A05:2021 - Security Misconfiguration / Cryptographic Failure

Description & Attack Proof of Concept

During directory enumeration of the /old/ directory discovered via robots.txt, an unauthenticated attacker can directly download the database dump file mediroza_db_backup_2019.sql (14.8 MB). Analysis of the SQL dump reveals complete table structures and confidential production records:

  • Table staff: Full names, clinical job titles, departments, corporate email addresses, direct phone numbers, South African National IDs, date joined, and exact monthly salaries in ZAR (e.g., Chief Surgeon at 145,000.00 ZAR/month).
  • Table shareholder: Corporate entity names, percentage equity holdings, active dividends, and valuations amounting to millions of ZAR.
Figure 4: Analysis of downloaded mediroza_db_backup_2019.sql exposing staff salaries and shareholder records Finding #2 Evidence (M3)

Business & Security Risk

Total Data Breach. Exposure of National IDs, phone numbers, and compensation creates severe liabilities under POPIA (Protection of Personal Information Act) and GDPR, enabling targeted spear-phishing, financial extortion, competitor intelligence gathering, and executive identity theft.

🛡️ Remediation Strategy

1. Immediately delete the /old/ directory and all associated database dump archives from public webroot.
2. Store database backups in isolated, encrypted, offline cloud storage (e.g., AWS S3 with KMS encryption and IP restriction).
3. Rotate all database credentials and conduct log audits to identify any IP addresses that accessed this file.

[HIGH] 3. Sensitive Directories Disclosed via robots.txt

HIGH (CVSS 7.5)
Affected Endpoint: https://medirozohospital.com/robots.txt
OWASP Category: A01:2021 - Broken Access Control

Description & Vulnerability Analysis

The hospital's robots.txt file is publicly accessible and contains entries intended to prevent search engines from crawling internal directories. However, because robots.txt is completely unauthenticated, it directly advertises the existence of sensitive paths:

User-agent: * Disallow: /patient/ Disallow: /staff/ Disallow: /old/
Figure 5: robots.txt disclosing restricted endpoints (/patient/, /staff/, /old/) directly to attackers Finding #3 Evidence

🛡️ Remediation Strategy

Do not rely on robots.txt for security (security through obscurity). Enforce strict HTTP 401/403 authentication at the web server reverse proxy level for internal endpoints and eliminate private path listings from robots.txt.

[MEDIUM] 4. Missing Modern HTTP Security Headers

MEDIUM (CVSS 5.4)
Affected Scope: Global Application Responses (All HTTP/HTTPS Responses)
OWASP Category: A05:2021 - Security Misconfiguration

Description & Vulnerability Analysis

Inspection of HTTP headers via curl -I confirms that the web application lacks essential defensive headers designed to instruct modern web browsers to prevent client-side attacks:

  • X-Frame-Options: Absent (Allows iframe embedding, exposing patients to Clickjacking).
  • Content-Security-Policy (CSP): Absent (Fails to restrict script execution, amplifying XSS impact).
  • X-Content-Type-Options: nosniff: Absent (Enables MIME-sniffing attacks).
  • Strict-Transport-Security (HSTS): Absent (Permits SSL-stripping and downgrade attacks).
  • Referrer-Policy & Permissions-Policy: Absent.

🛡️ Remediation Strategy

Configure LiteSpeed or .htaccess to enforce security headers across all responses:

Header always set X-Frame-Options "DENY" Header always set X-Content-Type-Options "nosniff" Header always set Strict-Transport-Security "max-age=31536000; includeSubDomains" Header always set Content-Security-Policy "default-src 'self'; script-src 'self'; object-src 'none';" Header always set Referrer-Policy "strict-origin-when-cross-origin"

[LOW / INFO] 5, 6 & 7. Server/CMS Banners, BREACH Risk & Email Harvesting

LOW / INFO

Summary of Observations

  • Finding #5 (Server & CMS Version Disclosure): HTTP response headers expose Server: LiteSpeed, X-Turbo-Charged-By: LiteSpeed, and meta tags revealing Mediroza CMS 1.4.2. This enables attackers to rapidly query vulnerability databases for target-specific exploits.
  • Finding #6 (BREACH Attack Possible): The server responds with Content-Encoding: deflate over HTTPS, which can allow side-channel statistical extraction of secrets (e.g., CSRF tokens) via chosen-plaintext compression length analysis.
  • Finding #7 (Email Harvesting): Publicly disclosed email address info@medirozohospital.com identified via WhatWeb, making personnel targets for automated spam and targeted spear-phishing campaigns.

🛡️ Remediation Strategy

Suppress the Server and X-Turbo-Charged-By response tokens, remove CMS version generator meta tags from HTML templates, and disable deflate compression on pages that output dynamic user reflection or CSRF tokens.

[CRITICAL] 8. SQL Injection in Patient Portal Login (M1 Auth Bypass)

CRITICAL (CVSS 9.8)
Affected Endpoint: https://medirozohospital.com/patient/login.php
OWASP Category: A03:2021 - Injection (SQLi)

Description & Attack Proof of Concept

The Patient Portal login form is vulnerable to Classic SQL Injection in the username parameter. The application concatenates raw, unsanitized user input directly into an SQL query:

-- Vulnerable Backend SQL Query Logic: $query = "SELECT * FROM users WHERE username = '" . $_POST['username'] . "' AND password = '" . $_POST['password'] . "'";

Exploit Payload: By submitting the payload admin' -- in the username field with any arbitrary password string (e.g. password123), the single quote terminates the string literal, and the SQL comment delimiter (-- ) truncates the password verification entirely. The backend executes:

SELECT * FROM users WHERE username = 'admin' -- ' AND password = '...'

Result: Immediate administrative login bypass into the Patient Care Management Dashboard.

Figure 6: Proof of Concept - Submitting SQLi payload admin' -- achieving full authentication bypass Finding #8 Evidence (M1)

Business & Security Risk

Complete authentication bypass enables unauthorized threat actors to access, manipulate, or delete patient medical records, prescribe false medications, alter lab test results, and seize control of hospital administrative functions.

🛡️ Remediation Strategy (Parameterized Prepared Statements)

Never concatenate user inputs into SQL strings. Refactor the authentication backend using PDO prepared statements:

<?php $stmt = $pdo->prepare("SELECT id, username, password_hash FROM users WHERE username = :username LIMIT 1"); $stmt->execute(['username' => $_POST['username']]); $user = $stmt->fetch(); if ($user && password_verify($_POST['password'], $user['password_hash'])) { // Authentication Successful $_SESSION['user_id'] = $user['id']; } ?>

[HIGH] 9. Sensitive PDFs Exposed & Weak Passwords Cracked (M2 Milestone)

HIGH (CVSS 8.2)
Affected Files: patient_report_1.pdf, patient_report_2.pdf, patient_report_3.pdf
OWASP Category: A02:2021 - Cryptographic Failures / A07:2021 - Identification & Auth Failures

Description & Password Cracking Workflow

Due to directory indexing on /patient/, three password-protected patient medical reports were downloaded directly. Cryptographic hash extraction and offline dictionary cracking was performed using Kali Linux toolsets:

  1. Extracted cryptographic hash using pdf2john:
    pdf2john patient_report_1.pdf > report1_hash.txt
  2. Launched dictionary attack using John the Ripper with the rockyou.txt wordlist:
    john --wordlist=/usr/share/wordlists/rockyou.txt report1_hash.txt
  3. Cracked Passwords:
    • patient_report_1.pdf: 123456 (Cracked in < 1 second)
    • patient_report_2.pdf: password (Cracked instantly)
    • patient_report_3.pdf: Weak symbol-based password
Figure 7: Index of /patient/ displaying unrestricted access to confidential medical report PDFs Finding #9 Directory Listing
Figure 8: Terminal showing pdf2john hash extraction and successful cracking of password (123456) Finding #9 Cracking (M2)
Figure 9: Decrypted patient report preview confirming exposure of patient diagnoses and treatment plans Finding #9 Privacy Violation (M2)

Business & Security Risk

Medical records contain Protected Health Information (PHI) including cardiac diagnoses, medication regimens, and patient identities. Exposing unauthenticated PDFs with trivial passwords violates patient privacy rights and triggers substantial legal liabilities.

🛡️ Remediation Strategy

1. Remove all PDF files from publicly indexed web directories.
2. Implement dynamic streaming endpoints that verify patient authentication and authorization before serving files.
3. Enforce cryptographic key management and enterprise-grade encryption (AES-256) rather than relying on weak user-supplied passwords.

5 Positive Security Controls Observed

Despite critical application-layer vulnerabilities, several strong baseline security controls were noted during testing:

  • Robust TLS Encryption: HTTPS is strictly enforced utilizing modern cipher suites (TLS_AES_256_GCM_SHA384), protecting data in transit from eavesdropping.
  • WAF User-Agent Blocking: Active Web Application Firewall (LiteSpeed ModSecurity) successfully intercepted default automated scanner User-Agents (e.g. Nikto, sqlmap) returning 403 Forbidden until evasion techniques were applied.
  • High Uptime: The web service remained consistently responsive (HTTP 200 OK) throughout legitimate browser sessions.

7 Conclusion & Capstone Reflection

The black-box penetration test against Mediroza General Hospital clearly demonstrates the compounding nature of web security misconfigurations. What began as basic information leakage in robots.txt and directory indexing directly facilitated the total compromise of sensitive internal databases, patient medical charts, and portal authentication mechanisms.

🎓 Security Practitioner Capstone Reflection

"This penetration testing assessment highlights that in cybersecurity, the smallest details often yield the greatest compromise. Advanced automated scanners were initially deflected by the firewall, but careful manual exploration of HTTP response headers, robots.txt, and directory listings uncovered critical systemic vulnerabilities.

The key takeaway from this assessment is that security is only as strong as its weakest link: strong SSL/TLS encryption cannot protect an organization when confidential database backups and patient diagnosis files are left exposed in publicly indexed web directories. Responsible disclosure and prompt remediation are vital to safeguarding patient trust and institutional integrity."
